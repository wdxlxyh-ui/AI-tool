Kiro Gateway 集成方案

将 Kiro Gateway 无缝集成到 AI 工具集中，提供统一的管理界面和 API 访问

一、方案概述

◆
设计目标

🔌 统一入口

将 Kiro Gateway 作为工具集的一个模块，用户无需记忆独立地址，通过工具集即可访问所有功能。

🔑 API Key 管理

提供界面查看和复制 API Key，一键生成不同用途的密钥，方便在多个应用中使用。

📊 服务监控

实时显示服务运行状态、端口占用、进程信息，支持一键启动/停止/重启。

📋 模型选择

列出所有可用模型及其特性，帮助用户选择适合的模型，提供调用示例代码。

二、功能设计

1. 服务管理

功能 描述 实现方式
启动服务 一键启动 Kiro Gateway 通过 subprocess 启动 venv/bin/python main.py
停止服务 安全停止运行中的服务 pkill -f kiro-gateway
状态检测 实时检测服务运行状态 pgrep 检查进程 + HTTP 健康检查
日志查看 查看服务运行日志 读取 /tmp/kiro-gateway.log

2. API Key 管理

Kiro Gateway 使用单一 API Key 保护网关，但我们可以为不同用途提供调用示例：

设计理念：Kiro Gateway 本身不支持多 API Key，但用户可以在自己的应用中使用同一个 Key 调用不同模型，实现"一个 Key 访问所有模型"。
场景 使用模型 说明
日常编码 claude-sonnet-4-5 平衡性能，适合大多数开发任务
快速原型 claude-haiku-4-5 快速响应，节省时间
复杂任务 claude-opus-4-5 最强性能，处理复杂推理
自动选择 auto 让 Kiro 自动选择最佳模型

client = OpenAI(
    base_url="http://10.230.169.128:8000/v1",
    api_key="kiro-gateway-2026-secret"
)

    model="claude-sonnet-4-5",
    messages=[{"role": "user", "content": "Hello!"}]
)

四、技术实现

后端 API 设计

端点 方法 功能
/kiro-gateway/ GET 管理界面主页
/kiro-gateway/api/status GET 获取服务状态
/kiro-gateway/api/start POST 启动服务
/kiro-gateway/api/stop POST 停止服务
/kiro-gateway/api/test POST 测试 API 连接
/kiro-gateway/api/logs GET 获取服务日志

认证集成

Kiro Gateway 自动从 kiro-cli 数据库读取认证信息，无需用户手动登录。界面会显示认证状态：

  • 已认证 凭证有效，可以正常使用
  • 即将过期 凭证将在 7 天内过期，建议刷新
  • 已过期 需要重新登录 kiro-cli
刷新凭证：运行 kiro-cli 命令即可自动刷新，无需额外操作。

五、集成步骤

  1. 创建 Blueprint 文件 app/kiro_gateway.py
  2. 创建模板文件 app/templates/kiro_gateway.html
  3. 在 app/__init__.py 注册蓝图
  4. 更新导航栏添加入口
  5. 重启 AI 工具集服务

六、优势总结

✅ 统一管理

所有工具集中在一个平台，降低使用门槛。

✅ 自动化

自动检测服务状态，自动管理进程。

✅ 用户友好

✅ 可扩展
